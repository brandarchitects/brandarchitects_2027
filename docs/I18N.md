# Mehrsprachigkeit

**Stand:** Nur Deutsch (de-CH), ohne URL-Präfix. Alles ist vorbereitet, damit Englisch (oder Französisch) ohne Umbau dazukommt.

## Wie es gebaut ist
| Ebene | Mechanik |
|---|---|
| URL | `app/[locale]/…`; next-intl `localePrefix: 'as-needed'` → DE ohne Präfix, weitere Sprachen mit (`/en/…`) |
| Sprach-Auflösung | `proxy.ts` (next-intl Middleware) |
| UI-Texte | `messages/de.json` – Buttons, Labels, Fehlermeldungen. Zugriff über `useTranslations` / `getTranslations` |
| Inhalte | Jedes Sanity-Dokument hat ein `language`-Feld; alle GROQ-Abfragen filtern danach. Plugin `document-internationalization` verbindet Übersetzungen |
| Links | Immer `Link` aus `i18n/navigation.ts` (setzt Präfix automatisch). Nie `next/link` direkt |
| SEO | `lib/seo/metadata.ts` erzeugt `hreflang`/`alternates` für alle aktiven Sprachen; Sitemap listet alle Sprachen |
| `<html lang>` | aus `localeTags` in `i18n/routing.ts` |

## Sprache 2 aktivieren – Schritt für Schritt (ca. 1 Claude-Code-Session + Übersetzung)
1. `i18n/routing.ts`: `locales: ["de", "en"]`, `localeTags.en = "en"`
2. `messages/en.json` anlegen: Kopie von `de.json`, übersetzen (Claude Code kann das; fachlich prüfen)
3. `sanity.config.ts`: `{ id: "en", title: "English" }` in `supportedLanguages` einkommentieren
4. Im Studio: bei jedem Dokument über das Übersetzungs-Menü die EN-Version anlegen und übersetzen. Reihenfolge: Website-Einstellungen → Startseite → Leistungen → Seiten → FAQ → Cases
5. Sprachschalter im Header aktivieren (Komponente vorbereitet: zeigt sich, sobald `routing.locales.length > 1`; siehe TODO in `components/modules/Header.tsx`)
6. `lib/seo/metadata.ts`: OpenGraph-`locale` pro Sprache (aktuell fix `de_CH`) – kleine Anpassung
7. `app/llms.txt/route.ts`: optional EN-Abschnitt ergänzen
8. Optional Pfad-Übersetzung (`/arbeiten/` → `/en/work/`): `pathnames` in `i18n/routing.ts` – next-intl übernimmt den Rest
9. Prüfen: `npm run build`, Sitemap, hreflang im Quelltext, Google Rich Results

## Was bewusst nicht gemacht ist
- Keine automatische Sprachweiche nach Browser-Sprache auf der Startseite (verwirrt Schweizer Nutzer, schadet SEO). next-intl-Default «locale detection» wird bei Aktivierung von EN auf `localeDetection: false` gesetzt, wenn gewünscht.
- Keine Feld-Lokalisierung (jedes Feld in jeder Sprache im selben Dokument) – Dokument-Lokalisierung ist für ganze Cases sauberer.
